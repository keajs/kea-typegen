# kea-typegen

Automatically generate types for `kea()` calls for [Kea 2.2+](https://keajs.org/)

## Docs

https://keajs.org/docs/intro/typescript

## Native TypeScript 7.1 beta

Run `kea-typegen check --compiler native` to compare your generated types with the Go-based compiler.
Use `kea-typegen write --compiler native` to apply the changes. To use the same compiler for
`check`, `write`, and `watch`, add `"compiler": "native"` to your `.kearc`. The CLI flag takes
precedence. By default, typegen selects the Go typegen engine when the project resolves TypeScript 7.x
and the classic engine (5.9.3) otherwise.

Typegen bundles TypeScript 7.1.0-beta and calls its synchronous JavaScript API. Your application's
TypeScript version can be installed independently. The Go process owns the semantic program.
Node loads syntax trees on demand for Kea visitors, source edits, plugins, and the existing printer.
Native watch mode runs a fresh project pass after a batch of changes and releases the compiler
between passes. Classic watch mode retains its incremental compiler.

The native engine uses your tsconfig and the new compiler's inference defaults. For example,
in a project that omits `strict`, inferred action payloads can now include `null` and `undefined`.
Kea logic syntax and plugin syntax nodes are still parsed with TypeScript 5.9. Plugins using typegen helpers can
continue using those helpers. Select `--compiler classic` for plugins that need the full classic
type checker. A plugin that directly imports `typescript` for its node factories must itself
resolve a compatible classic compiler.

## Go typegen

Install kea-typegen as usual. Its npm package selects a prebuilt worker for your OS and CPU.
Run `kea-typegen check --compiler go` to try it, or set `"compiler": "go"` in your project's
`.kearc` for `check`, `write`, and `watch`. TypeScript 7.x projects select it automatically.

Go runs the built-in visitors inside the TypeScript checker and generates inline and external
declarations. Node handles formatting and source edits. Packages can ship a portable Go
visitor as WebAssembly. Existing JavaScript plugins use the native TypeScript adapter when
needed. Use `--verbose` to see how many logics each path generated.

For a source checkout, build with `npm run build` and `npm run build:go` using Go 1.27 or
newer. If optional dependencies were omitted, a local build is also available with
`npm --prefix "$(npm root)/kea-typegen" run build:go`. The worker pins the same TypeScript
7.1.0-beta revision as the JS adapter. Its module path sits under the compiler's import
namespace to access the internal checker API.

## Inline mode

By default kea-typegen writes a `logicType.ts` file next to each logic. In inline mode it instead writes
a marked block of plain interfaces directly above the `kea()` call, tied together with kea's `MakeLogicType`:

```ts
// Generated by kea-typegen. Update if you're an agent, ignore if you're human.
export interface counterLogicValues {
    counter: number
}

export interface counterLogicActions {
    increment: (amount: number) => { amount: number }
}

export type counterLogicType = MakeLogicType<counterLogicValues, counterLogicActions>

export const counterLogic = kea<counterLogicType>({ ... })
```

- `--inline` (CLI) or `"inline": true` (`.kearc`) — inline mode for every logic.
- `--inline-paths a b` (CLI) or `"inlinePaths": ["./scenes/foo"]` (`.kearc`) — inline mode only for logic
  files under those paths; everything else keeps its `logicType.ts` file. Relative paths resolve against
  the root path. Use this to migrate a large project directory by directory.
- A file that already carries a generated inline block stays inline even without either option, so
  conversions never regress and single files can be converted with `kea-typegen write --inline -f <file>`.
- With `--delete`, the now obsolete `logicType.ts` files are removed on conversion.
- Untyped selector combiner parameters get their types written into the source, since `MakeLogicType` types
  them as `any`. An input that is one of the logic's own values indexes the generated interface
  (`(counter) => ...` becomes `(counter: counterLogicValues['counter']) => ...`), so the annotation follows
  the block on every regeneration; other inputs get their inferred type (`(id: number) => ...`).
- Logic metadata (`key`, `sharedListeners`, reducer actions from other logics, kea-forms input, ...) goes into a
  `logicMeta` interface. kea 4 takes it as the fourth `MakeLogicType` type argument; on kea 3, whose
  `MakeLogicType` has three, it is intersected instead: `MakeLogicType<V, A, P> & logicMeta`. The shape is
  picked from the kea your project resolves.
- Values and actions pulled in via `connect` are marked with their source logic, e.g.
  `user: UserType | null // userLogic`, and sorted: connected entries first, grouped by source logic
  (groups and entries alphabetical), then the logic's own entries alphabetically.
- Logics manually typed with `kea<MakeLogicType<...>>()` or a custom type are left alone entirely.
